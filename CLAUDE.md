# CLAUDE.md

This repository is a personal finance desktop app that keeps all data on the local machine in a fully encrypted database. It covers Electron security practices, encrypted storage, packaging and distribution, and an Apple-style interface.

## Read before starting

1. `docs/SPEC.md`
2. `docs/TASKS.md`: start from the first unchecked milestone
3. `docs/DECISIONS.md`

## Directory structure

```
src/
  main/       Electron main process: windows, database, encryption, file import/export
  preload/    Preload script: exposes only a typed allowlist of APIs
  renderer/   React + TypeScript + Zustand UI
  shared/     Types and validation schemas shared by the main and renderer processes
tests/
  unit/       Vitest
  e2e/        Playwright for Electron
  native/     Encrypted database under Electron, checks of the packaged app
scripts/      Repository checks and the seed data generator, run by npm scripts
```

## Working practices

- Write a plan before starting each milestone
- One commit per task, using Conventional Commits in English
- Check off tasks when done; record new decisions in DECISIONS.md
- Everything committed to GitHub (code, comments, docs, commit messages) is in English and concise: say what changed and why, not the step-by-step process. Commit messages use Conventional Commits with a short subject and at most a brief body.

## Common commands

```bash
npm ci && npm run setup:electron   # install scripts are off (.npmrc)
npm run dev
npm test
npm run test:e2e     # on Linux: as a non-root user, under xvfb-run
npm run test:native  # self-test of the built app (D012)
npm run lint && npm run typecheck && npm run format:check
npm run build        # build installers
npm run build:dir && npm run test:package   # unpacked build and its checks
npm run seed         # write a demo vault of fake data to .demo/user-data
npm run demo         # start the app on the demo vault
```

## Mandatory Electron security rules

- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`
- The renderer must never access Node or the database directly; it communicates only through the limited API exposed by preload
- Validate the arguments of every IPC channel in the main process with zod
- Strict CSP; never load remote content; no `eval`; block new windows and external navigation
- The master password stays in memory only briefly and is discarded as soon as the key is derived; passwords, keys and transaction details must never appear in logs
- Auto-lock after an idle timeout; on lock, clear the key and decrypted data from memory
- Tests and screenshots use only fake data generated by `npm run seed`
- Pin dependency versions; justify every new dependency
